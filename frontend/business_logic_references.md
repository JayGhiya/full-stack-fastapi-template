# Business Logic References

Detailed annotations for key data-model and infrastructure files identified in the **Business Logic Domain** section of [`AGENTS.md`](./AGENTS.md).

---

## Domain Overview

This frontend is a full-stack web application template built around two primary concerns:

1. **User Identity & Access Management** — registration, login, password recovery/reset, profile self-management, and role-based distinctions (regular user, superuser, verified account).
2. **Items Resource (CRUD)** — a generic first-class resource that authenticated users can create, read, update, and delete, scoped to individual ownership.

All backend communication flows through an **auto-generated OpenAPI client** that handles authentication tokens, HTTP validation errors, and cancellable requests.

Supporting areas include an **admin panel**, **user settings views**, and an **email utility** for transactional mail testing in end-to-end suites.

## File Annotations

### `src/client/types.gen.ts`
- **Category:** Generated domain models
- **Responsibility:** Contains auto-generated TypeScript interfaces and type aliases for every API request payload and response body. This is the single source of truth for domain-level data shapes (e.g., `UserPublic`, `ItemCreate`, `Token`, `HTTPValidationError`). Do not edit manually — regenerate from the OpenAPI spec.

---

### `src/client/core/ApiRequestOptions.ts`
- **Category:** API transport — request configuration
- **Responsibility:** Defines the `ApiRequestOptions` interface describing the options accepted by every outbound API call: HTTP method, URL, path/query/header/cookie/body/form-data parameters, and response type. Acts as the low-level contract between generated service methods and the HTTP layer.

---

### `src/client/core/ApiResult.ts`
- **Category:** API transport — response model
- **Responsibility:** Defines the `ApiResult` type representing a completed HTTP response, carrying the URL, status code, status text, whether the request succeeded, and the parsed response body. Consumed by error-handling logic and caller code to inspect outcomes uniformly.

---

### `src/client/core/CancelablePromise.ts`
- **Category:** API transport — async control
- **Responsibility:** Provides a `CancelablePromise<T>` wrapper that augments a standard Promise with an explicit `cancel()` method. Enables in-flight API requests to be abandoned cleanly (e.g., on component unmount or user navigation), preventing stale-data side-effects.

---

### `src/client/core/OpenAPI.ts`
- **Category:** API transport — global configuration
- **Responsibility:** Exports the `OpenAPI` configuration object that stores the base URL, credentials policy, auth token resolver (supports static string or async function), and default request headers. All generated service files reference this object, making it the central knob for switching API environments or injecting auth tokens.

---

### `src/routeTree.gen.ts`
- **Category:** Routing — generated route manifest
- **Responsibility:** Auto-generated by TanStack Router; enumerates every frontend route (page/view) and encodes their nested layout relationships. Provides full TypeScript inference for route paths and search-param shapes across the application. Do not edit manually — regenerate using the TanStack Router CLI/plugin.

---

### `tests/utils/mailcatcher.ts`
- **Category:** Test utility — email assertion
- **Responsibility:** Exposes helper functions that query a locally running Mailcatcher SMTP server (via its REST API) to retrieve and assert the content of transactional emails sent during end-to-end tests (e.g., verifying that a password-reset email was actually delivered with the correct link).
